Problem

Flower trail information is beautiful, but fragmented.

Seasonal flower spots change quickly. Visitors often rely on scattered blogs, outdated map listings, and social posts without knowing whether a route is still worth visiting today.

Kkotgil brings route curation, bloom-season filters, saved places, accessibility notes, and lightweight field reports into one mobile-first experience.

✿

Seasonal discovery

Filter flower trails by current bloom season and practical visit timing.

⌁

Walking routes

Map-based routes, distance cues, and saved places for repeat visits.

✓

Field reports

Short user submissions help validate real-world conditions before a wider release.

Current pilot

Starting dense, then expanding region by region.

Kkotgil is beginning with a Seoul southeast pilot to validate route quality, saved-route behavior, and field-status updates before national expansion.

Technology plan

Built for a lean AWS-backed pilot.

Kkotgil’s current backend uses small Go API services with a Supabase/PostGIS data layer. AWS credits will help move the mobile backend from private testing toward a stable production pilot.

API hosting

Host Go-based backend services for routes, community updates, and user features with a low-cost architecture.

Route data delivery

Serve route and map-related static data efficiently as user traffic grows beyond private testing.

Observability

Monitor logs, errors, latency, and application health during the Seoul pilot.

Future AI support

Classify field reports, summarize bloom status, and recommend routes with human review and cost controls.
